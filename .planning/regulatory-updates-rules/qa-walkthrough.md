## Summary

87 total criteria · 17 PASS · 56 FAIL · 7 PARTIAL · 7 SKIPPED.

The page is in a critical state for any mutation beyond the initial Register form: **the Edit modal, the Business-Owner-assign modal, the PDF-upload widget on the detail panel, every workflow action (add step, advance, delete step, reorder, per-step deadline), every article action, and the entire timeline activity feed are all running on local store mutations with no API calls**. They look correct in the UI optimistically and then evaporate on hard-reload. The headline persistence bug repeats across at least 7 sub-features. Hard-delete is also wrong — it issues a soft-delete server-side.

The only mutations that hit the DB this run were:
- `POST /api/circulars` (Register New Circular form) — works.
- `DELETE /api/circulars/[id]` — returns 200 OK but the server-side handler does a soft-delete (`UPDATE … SET deleted_at = now()`), not a hard delete.
- `circular_timeline` "Circular created" row + `audit_logs` "circular.create" row are written by the create path — but they don't render in the detail panel's Activity tab.

## Reproduction

### Bug #1 — Workflow is 100% client-side
1. Open any circular's detail panel.
2. Click **Workflow** tab → 10 steps render.
3. Click **Add step** → enter `"QA Custom Step"` → click **Add**. Step appears in UI.
4. Open Network panel → `filter: workflow/steps` → **0 requests**.
5. SQL: `select * from circular_workflow_steps where circular_id='<id>'` → 0 rows.
6. Hard-reload → "QA Custom Step" is gone.
7. Code pointer: `src/stores/circular-store.ts:911-960` — `addWorkflowStep` only mutates the in-memory store; no `api.post('/api/circulars/.../workflow/steps', ...)` call.

### Bug #2 — Edit Save does not PATCH
1. Open detail → **Edit Circular** → toggle a department, change description, click **Save Changes**.
2. Modal closes. Detail Overview shows fresh "Pending Approval" panel.
3. SQL: `select description, reference_url, departments from circulars where id='<id>'` → unchanged.
4. SQL: `select * from circular_pending_edits where circular_id='<id>'` → 0 rows.
5. Network log: no `PATCH` to `/api/circulars/<id>`.
6. Hard-reload → original values restored.
7. Code pointer: `src/stores/circular-store.ts updateCircularPending` (local-only).

### Bug #3 — Assign Business Owner does not PATCH
1. Detail → **Assign Business Owner** → select a department → confirm.
2. Network log: no PATCH.
3. SQL: `select business_owner_department from circulars where id='<id>'` → null.
4. Hard-reload → chip gone.

### Bug #4 — PDF upload does not persist
1. Detail Overview → "Upload Circular PDF" zone → upload a PDF.
2. UI shows no "Circular PDF attached" green panel.
3. Network: no PATCH/POST.
4. SQL: `pdf_url IS NULL`.

### Bug #5 — Add Article does not POST
1. Detail → **Add Article** → fill required fields → checklist item → **Save**.
2. Network: no POST to `/api/circulars/<id>/implementations`.
3. SQL: `select * from circular_articles where circular_id='<id>'` → 0 rows.

### Bug #6 — Delete is a soft-delete
1. Detail → **Delete Circular** → confirm.
2. Network log: `DELETE /api/circulars/<id>` → 200 OK.
3. SQL: `select id, deleted_at from circulars where id='<id>'` → row still exists with `deleted_at` populated.
4. Code pointer: `src/app/api/circulars/[circularId]/route.ts:122-132` — `supabase.from('circulars').update({ deleted_at: new Date().toISOString() })` instead of `.delete()`.

### Bug #7 — Workflow steps not seeded on create
1. Register a new circular.
2. SQL: `select count(*) from circular_workflow_steps where circular_id='<new id>'` → 0.
3. Migration 025 (`supabase/migrations/025_circular_workflow.sql`) only ALTERs columns; no `INSERT … SELECT FROM default_steps`. No trigger on `circulars` insert.
